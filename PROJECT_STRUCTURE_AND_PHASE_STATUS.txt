============================================================
1. PROJECT OVERVIEW
============================================================

Project name:
SOP Project - Tamil Nadu synthetic population and policy simulation foundation.

Main objective:
Build a reliable data foundation and synthetic population pipeline for later
policy simulation workflows.

Tamil Nadu scope:
The current implementation is scoped to Tamil Nadu. Phase 1 constructs a Tamil
Nadu reference population/template from trusted data sources and produces
official marginal/calibration datasets. Later phases use this state-scoped
foundation rather than a national synthetic population.

Why the project creates a synthetic population:
Policy simulation needs individual and household-like records with consistent
features such as age, gender, district, urban/rural status, education,
employment, household size, income, consumption, and social group. Real survey
microdata can be sensitive, incomplete for policy needs, or not shaped for
simulation. Synthetic population generation creates candidate populations that
preserve useful statistical structure while giving later simulation modules a
controlled population artifact to operate on.

How policy simulation will use the synthetic population:
Later policy engines can evaluate eligibility rules, simulate alternative policy
designs, run Monte Carlo/uncertainty workflows, compare outcomes, and generate
recommendations using the selected and calibrated synthetic population. Phase 5
will calibrate/reweight the selected Phase 4 population before those later
policy simulation components are used.

Simple architecture:

Data Sources
    ->
Phase 1 - Data Foundation
    ->
Phase 2 - Policy-Data Compatibility
    ->
Phase 3 - Synthetic Population Generation
    ->
Phase 4 - Population Validation
    ->
Phase 5 - Calibration/Reweighting
    ->
Later Policy Simulation Components

This document currently audits and explains Phases 1-4. Phase 5 is not
implemented here.

KEY CONCEPTS IMPLEMENTED
Variable availability:
Determines whether a required variable is exactly available, available through
an approved proxy, aggregate-only, or missing.

Joint availability:
Checks whether required variables can be used together for a policy.

Geography compatibility:
Checks whether the data geography supports the policy geography.

Temporal compatibility:
Checks whether the data recency is acceptable for the policy requirement.

Critical requirements:
Variables marked critical can block readiness if unavailable.

Reliability score:
Numeric score summarizing how reliable the data-policy match is.

BOOTSTRAP
How it works:
Bootstrap resamples complete records from the reference training data.

What it learns/does:
It does not learn a parametric model. It preserves observed records and their
relationships by sampling from the existing reference dataset.

Strengths:
Very high distribution and relationship fidelity; simple and robust baseline.

Limitations:
Low novelty and weak privacy characteristics because exact row-level feature
duplicates are expected.

Current implementation status:
Implemented, trained/persisted, sampled, finalized, and included in Phase 4.

Current population artifact:
artifacts/synthetic_populations/SYNPOP-BOOTSTRAP-REPRESENTATIVE-12000-142-ACCEPTANCE/population.csv

GAUSSIAN COPULA
How it works:
Models variable distributions and dependencies using a copula-style approach.

Strengths:
Can generate novel rows and preserve many marginal distributions very well.

Limitations:
May weaken important categorical/geographic relationships.

Current implementation status:
Implemented, trained/persisted, sampled, finalized, and included in Phase 4.

Current population artifact:
artifacts/synthetic_populations/SYNPOP-GAUSSIAN_COPULA-REPRESENTATIVE-12000-144-ACCEPTANCE/population.csv

CTGAN
Meaning:
Conditional Tabular GAN.

How it works:
Uses a generator/discriminator training setup for tabular data. The generator
learns to produce synthetic records while the discriminator learns to distinguish
synthetic from reference-like records.

Why useful for tabular data:
It can model nonlinear and mixed-type tabular patterns and produce novel
records.

Actual SDV implementation:
backend/app/modules/synthetic_population/generators/neural.py wires CTGAN to
SDV's CTGANSynthesizer.

Training, persistence/loading, sampling:
Training is driven by generator_training.py and neural_training.py. The model is
saved, loaded, and sampled through the neural generator and sampling services.

Current population artifact:
artifacts/synthetic_populations/SYNPOP-CTGAN-REPRESENTATIVE-12000-146-ACCEPTANCE/population.csv

TVAE
Meaning:
Tabular Variational Autoencoder.

How it works:
Uses an encoder to map tabular records into a latent representation and a
decoder to generate records from that latent space.

Strengths:
Can generate novel records and learn compact representations of mixed tabular
data.

Limitations:
With the current lightweight settings, it has weaker fidelity on several
categorical variables than Bootstrap and Gaussian Copula.

Actual SDV implementation:
backend/app/modules/synthetic_population/generators/neural.py wires TVAE to
SDV's TVAESynthesizer.

Training, persistence/loading, sampling:
Training is driven by generator_training.py and neural_training.py. The model is
saved, loaded, and sampled through the neural generator and sampling services.

Current population artifact:
artifacts/synthetic_populations/SYNPOP-TVAE-REPRESENTATIVE-12000-148-ACCEPTANCE/population.csv

12. PHASE 4 - POPULATION VALIDATION
============================================================

PURPOSE
Validate candidate synthetic populations before policy simulation. A generated
population existing does not automatically mean it is a good synthetic
population.

IMPORTANT MODULES
backend/app/modules/population_validation/service.py
backend/app/modules/population_validation/metrics.py
config/population_validation/scoring.yaml

VALIDATION COMPONENTS
Distribution Fidelity:
Compares synthetic variable distributions against the reference distribution.

Numerical KS:
Kolmogorov-Smirnov style comparison for numerical variables.

Wasserstein distance:
Measures distance between numerical distributions.

Jensen-Shannon divergence:
Measures difference between categorical probability distributions.

Total Variation Distance:
Measures categorical distribution distance.

Missingness comparison:
Checks whether missing value behavior is preserved.

Pearson correlation:
Linear relationship preservation for numeric variables.

Spearman correlation:
Rank relationship preservation for numeric/ordinal variables.

Cramer's V:
Categorical association preservation.

Eta / correlation ratio:
Relationship strength for mixed categorical/numeric associations.

Constraint/data validity:
Checks hard constraint violations and data validity.

Official marginal comparison:
Compares selected synthetic marginals with official Tamil Nadu marginal files.

Statistical similarity:
Overall statistical closeness to reference/holdout data.

Composite quality score:
Weighted combination of distribution fidelity, correlation preservation, data
validity, and statistical similarity.

Critical gates:
Specific threshold checks that can fail a population even when the composite
quality score is high.

STATUS MEANINGS
PASS:
Population passes configured quality and critical validation gates.

FAIL:
Population fails one or more configured critical gates or required thresholds.

PASS_WITH_WARNINGS:
The implementation supports warning-style reporting. The current comparison
shows Bootstrap as PASS with one warning rather than a separate
PASS_WITH_WARNINGS status in the comparison table.

WHY HIGH QUALITY CAN STILL FAIL
A model can have a high composite quality score but still FAIL if a critical
gate is below threshold. This is intentional: a population may be good overall
but still unsuitable if it breaks an important variable or relationship needed
for policy use.

20. FINAL SUMMARY
============================================================

SOP_PROJECT is a Tamil Nadu-focused synthetic population foundation for later
policy simulation.

Phase 1 builds the data foundation: reference template, variable dictionary,
source registry, calibration tables, metadata, and reports.

Phase 2 checks whether policy requirements can be supported by available data,
including exact variables, proxies, temporal suitability, geography, critical
requirements, and readiness decisions.

Phase 3 trains and persists four candidate synthetic population generators:
Bootstrap, Gaussian Copula, CTGAN, and TVAE. It generates 12,000-row candidate
populations for all four and writes the Phase 4 validation manifest.

Phase 4 validates all four candidate populations using distribution fidelity,
relationship/correlation preservation, data validity, statistical similarity,
official marginal comparison, composite quality scoring, and critical gates.

Bootstrap is currently selected because it is the highest-scoring candidate
that passed all configured Phase 4 gates. Gaussian Copula, CTGAN, and TVAE are
technically working generated populations, but their current candidate
populations fail one or more validation gates.
