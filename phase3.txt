The objective of Phase 3 is:

> Use the trusted Tamil Nadu reference template and Phase 2 policy-data requirements to train statistical generative models and create artificial Tamil Nadu populations that preserve important demographic, socioeconomic and policy-relevant relationships while remaining reproducible, configurable, traceable, and explicitly labelled as synthetic.

Do NOT implement downstream policy simulation in this phase.

# 4. CRITICAL DATA INTEGRITY RULE

Never confuse:

```text
REFERENCE DATA
```

with:

```text
SYNTHETIC DATA
```

All generated records must be clearly artificial.

Never claim generated records represent actual identifiable residents of Tamil Nadu.

The synthetic population exists for:

```text
policy simulation
statistical experimentation
scenario analysis
population modelling
```

not for representing real individuals.

---

# 5. PURPOSE OF THE SYNTHETIC POPULATION

The future Policy Engine will need artificial individuals that behave statistically like the reference Tamil Nadu population.

Example:

```text
Synthetic Person

Age                 27
Gender              Female
District            Madurai
Urban/Rural         Urban
Education           Undergraduate
Employment          Unemployed
Household Size      4
Household Income    ₹240,000
...
```

This person is:

```text
ARTIFICIAL
```

but the overall generated population should reproduce plausible statistical patterns derived from trusted reference data.

---

# 6. SYNTHETIC POPULATION IS NOT RANDOM FAKE DATA

Do NOT create fake people using independent random generators.

Incorrect:

```python
age = random.choice(age_values)

gender = random.choice(genders)

education = random.choice(education_levels)

employment = random.choice(employment_statuses)
```

This destroys dependencies.

For example, it could produce:

```text
Age = 8
Education = Postgraduate
Employment = Salaried Employee
Marital Status = Married
```

The system must learn multivariate statistical relationships.

---

# 15. WHY THE BASELINE IS REQUIRED

Do not assume complex neural generators are superior.

The baseline tells us whether models such as CTGAN actually improve:

```text
distribution similarity
joint relationships
rare categories
logical validity
```

If CTGAN performs worse than simpler methods, the system should be able to detect that in the next validation phase.

---

# 40. HARD VS SOFT RULES

Separate:

```text
HARD CONSTRAINT
```

from:

```text
STATISTICAL ANOMALY
```

Examples:

```text
age = -1
```

Hard invalid.

But:

```text
age = 19
education = Undergraduate Graduate-equivalent
```

may be rare but plausible depending on category definitions.

Soft anomalies should be flagged, not automatically deleted.

---

# 42. POST-GENERATION REPAIR

Use repair only for:

```text

```

# 66. DERIVED VARIABLES

Avoid asking models to learn variables that can be deterministically derived.

Example:

```text
age
```

can generate:

```text
age_group
```

after synthesis.

Do not necessarily train on both:

```text
age
age_group
```

unless there is a strong reason.

Prefer:

```text
generate base variable
derive deterministic field afterward
```

This prevents inconsistencies.

---

# 67. APPROVED DERIVATIONS

Use Phase 2-approved derivations.

Example:

```text
is_elderly = age >= 60

is_youth = configured age rule

annual_income =
monthly_income × 12
```

Only derive variables using registered deterministic transformations.
